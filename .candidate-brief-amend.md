## Change 1 — renderer: one `cos`/`sin` per (rotor, order), angle addition per mic

In `render_revised`, the inner mic loop currently evaluates `np.cos(arg + alpha[m])` once **per
microphone**, i.e. 8 full-length transcendental passes per (rotor, order): about 2.9e9 `cos`
evaluations for a 16 s, 4-rotor, 130-order clip. Main has directed an equivalent-performance
cleanup:

- Compute `c = np.cos(arg)` and `s = np.sin(arg)` **once** per (rotor, order).
- Combine per microphone by angle addition:
  `cos(arg + alpha_m) = cos(arg) cos(alpha_m) - sin(arg) sin(alpha_m)`.
- Fold `env` into the two full-length arrays once (`ec = env * c`, `es = env * s`), then accumulate
  per mic as `audio[m] += g_m * (cos(alpha[m]) * ec - sin(alpha[m]) * es)` with
  `g_m = sqrt(line_gain[m, r])`. Keep it a per-mic loop with light temporaries — do NOT build an
  `(n_mics, n_native)` outer product, that is a 45 MB allocation per order.

**This must be numerically equivalent, not merely close.** Two absolute requirements:

1. **Preserve the RNG draw order exactly.** `rng_eps.standard_normal(n_native - 1)` and then
   `rng_alpha.uniform(0.0, 2*pi, size=n_mics)`, in that order, once per (rotor, order), with the
   same sizes and the same skip conditions (the `k * f0 > native Nyquist` `continue` must still
   happen before any draw, exactly as now). A rendered clip at a given seed must be the same
   waveform as before, up to floating-point reassociation only.
2. Do not change any amplitude, gain, floor or phase semantics. `eps` is still added into `arg`
   before the mic loop (it is source-shared across mics) and still never enters `physical_rps`.

Say in a short comment why the angle addition is there (2 trig passes instead of `n_mics`), so the
next reader does not "simplify" it back.
