# Addendum 12 — MANDATORY import-provenance guard before any validation or job

Precedence: addendum 12 > 11 > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3 > 2 > addendum > brief. This is an
existing mandatory repo guard, **not** extra infrastructure. It applies before **any** Python
validation and before **any** job.

## 61. The hazard, measured

`omp --cwd <worktree>` **alone does not guarantee** that `.envrc` was activated. The `.venv` is
**shared** with the main checkout (mk-worktree links it and never runs `uv sync`), and it carries
an **editable install pointing at the MAIN checkout's `src`**. Measured `sys.path` inside this
worktree:

```
.worktrees/revised-phase/src                 <- only present when .envrc/direnv applied
<main>/.venv/lib/python3.12/site-packages
<main>/src                                   <- ALWAYS present, via the editable install
```

Consequence, verified by direct experiment: with a main-pointing `PYTHONPATH`,
`experiments.stochastic_fit.stage2` resolves to
`<main>/src/experiments/stochastic_fit/stage2.py` and `revised_eval` raises `ImportError`.

**This is not hypothetical for your work.** `stage2.py` exists in **both** checkouts, so your AA
rewrite can silently fail to be exercised while tests still appear to pass against main's copy.
Modules that exist only here (`revised_eval.py`, `phase_kernel.py`, `revised_phase.py`) fail
loudly instead — which is the only reason round 1 was safe: a successful `--check` proves the
worktree `src` preceded main's on that run.

## 62. Required of every validation run and every smoke proof

- Ensure the runtime imports **this worktree**: use the project's direnv exec / worktree env, or
  put `<worktree>/src` **first** on `PYTHONPATH` explicitly. Do not rely on `--cwd` or on
  metadata alone.
- **Record, in the smoke proof itself**, the resolved paths of:
  - `experiments.__file__`
  - `revised_phase.__file__`
  - `stage2.__file__`
  and assert each is under `.worktrees/revised-phase`. Fail the run if any is not.
- Make this a real assertion in the evidence you emit, not a comment. A run whose import
  provenance is unproven does not count as validation.
- Never run `uv sync`, and never modify `uv.lock`.
- For remote jobs, imports must point at the **pushed job checkout** — record the same three
  paths there too.

Metadata-only or cwd-only claims of import provenance are explicitly insufficient.
