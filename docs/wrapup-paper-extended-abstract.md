We establish a first serious attempt at rotor speed estimation from drone ego-noise. Due to the harmonic structure of rotor noise, this problem is basically a problem of multi-pitch estimation. However, it is very different in practice from musical multi-pitch estimation: four "notes" are played without stopping, their fundamental frequencies change continuously, they are not tied to any regularly spaced grid of values (how notes are tied to semitones), their pitch trajectories are often very close to each other and often cross. Therefore, many structural characteristics which are desirable for musical multi-pitch estimators are actively harmful for drone motor speed predictors, and hence, successful models for former task cannot be meaningfully reused for the latter without changes. We thus consider several well-established baseline architectures for musical multi-pitch estimation (LateDeep, BasicPitch, HarmF0, HPPNet) and do a series of modifications on them to make them suited for the task.

First, we adapt the output structure of the models of the task. All but one (LateDeep) models in question use an established output format for musical applications: salience map with onsets/offsets sections (LateDeep does not have explicit onsets/offsets). First, we drop onsets and offsets and leave only pitch map, since we assume that each of four rotors is always present (albeit maybe with speed zero). Models which are only modified thus far can be trained as rotor speed predictors, but perform very poorly, primarily due to the fact that simply representing four close rotor trajectories as pitch trajectories via joint salience map which has the logarithmic scale ar is lossy - it is impossible to even decode such map back to trajectories precisely, even if we somehow can always correctly choose which rotor chooses which path after they cross (e.g. via chunkwise Hungarian matching against ground truth), and during real inference we actually cannot. Hence, this representation, which is suitable for polyphonic music representation, is unsuitable for our task, because we need to preserve __rotor identity__ - which has no meaningful analogue in music, especially piano music - and we have to work with continuously changing pitches which are very close to each other. We resolve this problem via migrating to 4-channel salience map, where each channel represents a rotor, and using linear frequency grid in 0-150 Hz range, which is our range of interest, thus solving both the problems of rotor identity preservation and precisions. Such representation is a virtually lossless substitute for the rotor speed time series, and baseline models start to yield meaningful results after migrating to this output representation.

At this point, we select the best performing model after output adaptation (HPPNet) and consider if other aspects of its design are well-suited for the task. Its key design feature - harmonic-dilated convolutions - is suited for reacting to harmonic lines in the spectrum, which is clearly relevant; however, the default number of harmonics uses (nine) is clearly lacking when we sometimes have strong motor noise harmonics at 42th and 84th orders, so we extend this number. Next, FreqGroupLSTM in its literal reapplication cannot track the movement of single rotor between neighboring frequency bins, and since rotors - unlike piano notes - move between bins all the time, this layer cannot really track the rotors. Hence, we replace it with ConvLSTM and significantly improve the performance. Finally, we consider the fact that CQT input representation, while providing excellent resolution at BPF level, fundamentally cannot utilize the fact that close rotors can be separated easier at higher harmonics (which is apparent when using linear STFT). In order to better utilize this fact, we propose pyramidal multi-resolution STFT representation akin to FPNs and efficiently adapt harmonic-dilated convolution structure to this linearly scaled representation; as a result we get a model which performs on par with CQT-based ones when all useful information is concentrated in lower harmonics, but better when useful information is present in higher harmonics. The resulting model has an additional advantage of operating at linear frequency scale throughout, allowing us to get rid of superresolution head and allowing us to trivially extend the model to higher max speed range if necessary. We dub the final model HRSPNet (harmonic-rotor-speed-predictor network), since it is already quite far from the original HPPNet.

We then compare the model with a family of regressor models, which is a basic convolutional model proposed in the only previously published paper on rotor speed prediction from audio (Quiet Drones 2026 paper) and several its modifications, and find that it outperforms all of them; regressor models fail to track fine variations of drone trajectory and tend to output smoothed averaged out trajectories. We, however, find that no model is able to transfer well to one drone while being trained on a single completely different one; given the scarcity of telemetry-annotated drone noise data (we have only two distinct drones), we cannot thus claim that we proposed a generically useful way of training rotor speed predictors. Therefore, we propose a synthetic pretraining scheme using a physically-grounded probabilistic generative model of drone noise, which we validate via fitting it to the existing drone ego-noise recordings. We then show that models pre-trained on synthetic noises produced by wide array of plausible parameter realizations of such model learn generically useful features and produce useful predictions on real data without any fine-tuning; and a short fine-tuning on real drone data leads to the model which outperforms one trained only on real data while still maintaining precision on synthetic samples or on real drones not seen during fine-tuning. We additionally show that using more simplistic and naive approaches to synthetic data generation does not lead to such favorable results.

So we have made a twofold contribution: an efficient architecture for predicting the rotor speeds from quadrotor ego-noise and a generative model of such noise suitable for efficient large-scale pretraining of such models.
