# Addendum 3 — further FROZEN evaluator decisions

Precedence: addendum 3 > addendum 2 > addendum > brief. These are evaluator-scope and bind you
directly.

## 17. LTAS — absolute level, no per-arm normalization

- Retain **ABSOLUTE-level LTAS error**. No arm-specific peak or band normalization.
- A relative-shape LTAS may be reported as a **secondary diagnostic** only.

## 18. Periodogram scaling — one scale, derived from the real clip

- If any unit-mean periodogram scaling is used, derive the scale **ONCE from the real clip** and
  apply that same scale to **all** models/arms.
- **Never** normalize a synthetic arm independently. Per-arm normalization would let an arm
  launder a level error into an apparent shape match.

## 19. Initial spectral gate — Main's simple frozen form

- **DREGON:** paired mean `delta composite < 0` **and** upper one-sided 95% bound `< 0`.
- **DREGON LTAS:** point non-regression, plus a **baseline-variability-calibrated tolerance**
  for the uncertainty allowance.
- **Michael's:** NLL/LTAS non-regression tolerances, **conditional on FLY124**, calibrated on
  baseline data **before** any candidate is evaluated.

## 20. Null-variation calibration — propose the rule UP FRONT

You must propose the **exact null-variation calibration rule** as part of your proposals doc,
and it must be frozen before candidates run. Tolerances are **never** tuned after seeing
candidate results. This is the single most important integrity property of the instrument:
build it so a tolerance cannot be retro-fitted — read the calibration from the frozen manifest,
and fail loudly if the manifest lacks it rather than defaulting to something permissive.

## 21. Required honesty statement in the output

The benchmark selection is **adaptive over up to 8 rounds**. Therefore the bootstrap intervals
this instrument produces are **decision/uncertainty summaries, not fresh-unseen confirmation**.
The evaluator's saved output and any report must **not** claim an independent final
generalization proof. Emit this caveat as a field in the saved metrics/decision record, so it
travels with the numbers instead of living only in prose.

## 22. Michael fixed-recording gate — EXACT arithmetic (corrects the brief)

The brief's phrase "equally weighted candidate/baseline MAE ratios ... aggregate <= 1.05" was
shorthand and is **easy to implement wrongly**. The correct computation is a **ratio of
equally-weighted MAEs**, not a mean of per-regime ratios:

```
E_rig_baseline  = (E_standby_baseline + E_ramp_baseline + E_cruise_baseline) / 3
E_rig_candidate = (E_standby_candidate + E_ramp_candidate + E_cruise_candidate) / 3
gate: E_rig_candidate / E_rig_baseline <= 1.05
```

**Do NOT** compute `(r_standby + r_ramp + r_cruise) / 3` with `r = E_new/E_base` per regime.
That form gives a tiny standby MAE disproportionate leverage and invites near-zero
denominators. The frozen form implements equal regime weighting **of the primary MAE itself**,
consistent with the user's "on average" criterion.

Still report **every regime and its own ratio separately** alongside the aggregate. DREGON is
unchanged by this clarification.
