# Addendum 6 — instrument review findings (required fixes)

Precedence: addendum 6 > 5 > 4 > 3 > 2 > addendum > brief. From the read-only instrument
reviewer, spot-checked against your source. Six items. Several are **gate-integrity** bugs: they
let a run PASS that should not.

## 31. `--check` cannot read a candidate export (crashes)

`read_export` (~386) and the `export_render` path only parse the **legacy** `summary['clips']`
layout, aggregate into `ModelParams`, then call `stage2.render_from_export` and
`predicted_m`. Candidate 1's export is `model_family='shared_shaft_ou'` with
`parameters`/`training_provenance` — it currently **crashes in `read_export`**, and the
`physical_rps` diagnostic is silently absent.

Required: dispatch on `model_family`. For `shared_shaft_ou`, call the candidate-owned API
`revised_phase.render_revised(...)` and `revised_phase.predict_spectrum(...)` and consume the
structured result's `physical_rps` for the **diagnostic-only** physical-shaft MAE. You do **not**
implement the candidate model — you dispatch to it and fail with a clear message if it is absent.
Never silently drop the diagnostic.

## 32. Michael's is missing its addendum-3 §19 gates

Michael's currently gets only the MAE-ratio gate. The **conditional-on-FLY124 NLL and LTAS
non-regression gates are never added**. Worse, `summarize_prepare` collapses null variation to a
single recording, so the LTAS tolerance comes out `None` instead of being calibrated.

Required: add both conditional-on-FLY124 gates, with tolerances from **conditional blocks**
within FLY124 (that is what "block variation conditional on FLY124" means) rather than an
across-recording quantity. A tolerance of `None` must **fail loudly**, never wave a gate through.

## 33. DREGON gate passes on partial cohorts

`enough_clusters=bool(len(rows) >= 2)` at ~1146 and ~1198 accepts **two** paired recordings, and
the insufficient-support reports never fail anything. The gate can therefore pass on 2-4
recordings while the frozen cohort is **all five** no-source room2 recordings.

Required: require the full frozen cohort from the manifest — not a `>= 2` floor. An
insufficient-support `SupportReport` (`sufficient=False`) must **fail** the check, per the
"report it, never pad or repeat" rule. Missing coverage is a stop condition, not a pass.

## 34. `pit_mae` silently truncates to the shorter timeline

At ~961: `n = min(a.shape[-1], ref.shape[-1])` then `a, ref = a[:, :n], ref[:, :n]`. A short or
mis-rendered candidate wav therefore gets **scored on a different timeline** instead of being
rejected.

Required: **reject** a length mismatch outside a tight, explicitly stated tolerance — raise, and
let the gate fail. Truncation to the shorter array is exactly how a broken render scores well.
This pairs with addendum 4 §26: keep the masks/times as provenance.

## 35. No leakage check on candidate provenance

The candidate's `training_provenance` / fit supports and the manifest hash are never checked
against the held-out supports. Required: verify the candidate was not trained on any held-out
support, and fail on overlap. This is the F5 "no held-out raw-sample support leakage" check at
manifest level.

## 36. Baseline exports and dataset versions are not pinned

Baseline export **hashes** and dataset versions are not recorded/verified, so a file can change
between `--prepare` and `--check` — altering the supports — while the calibration manifest digest
still compares equal.

Required: pin and verify content hashes of every baseline export plus dataset versions, and fail
if anything moved between prepare and check. The manifest digest must cover the **referenced
artifacts**, not just the manifest text. This is the frozen-manifest promise in the contract.
