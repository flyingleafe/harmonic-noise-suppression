## Main's frozen calibration (record it, do not implement a calibrator)

Over fixed baseline predictive draws, on the actual **unnormalized** fit risk that
`composite_risk` returns — not a reported per-second or per-frame score:

    U = sum_i a_i (1 - I_i / M_i)          the untempered FIT-risk log-gain score
    H = sum_i a_i                          the total exposure
    J = Var(U)                             over the fixed baseline predictive draws
    T = J / H                              the frozen scalar temperature

and the objective is

    L / T + one prior

## The change

The code currently **multiplies** by `config.temperature`. It must **divide** by it. Three sites:

1. **Module docstring, the objective block (currently line 72).** Change
   `L = temperature * sum_i ...` to the divided form, e.g.
   `L = (1 / temperature) * sum_i a_i * sum_{m, f in band} (I_i / M_i + log M_i)`, and in the
   paragraph just below it (currently lines 79-82) state Main's frozen definition verbatim in
   symbols: `U = sum_i a_i (1 - I/M)`, `H = sum_i a_i`, `J = Var(U)` over fixed baseline predictive
   draws, `T = J / H`, objective `L / T + one prior`; and say explicitly that the calibration is
   matched to the actual UNNORMALIZED risk returned by :func:`composite_risk`, never to a reported
   per-second score. Keep the existing "calibrated then frozen; this code reads it, it never tunes
   it" sentence.
2. **`fit_revised`'s chunk loss (currently line 1470):**
   `loss = config.temperature * model.chunk_risk(...)` becomes a division by the temperature.
3. **`infer_carrier`'s chunk loss (currently line 1743):** same change,
   `loss = cfg.temperature * model.chunk_risk(0, chunk)` becomes a division.

Divide once per chunk loss, exactly where the multiplication is now — do not move the factor into
`chunk_risk` or into `composite_risk`, which must keep returning the untempered risk (Main's
calibration is defined on it, and the evaluator reads it).
