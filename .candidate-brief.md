## 1. What candidate 1 is

One stochastic process per rotor plus one independent acoustic phase diffusion, fitted by
**ordinary Adam on a single plug-in composite MAP objective**. Nothing else. No EM, no Kalman
smoother, no particle filter, no Laplace approximation, no crossing graph, no per-harmonic latent
inference, no second carrier spline, no free `D` per order.

For rig with rotors `r`, clips `c`, orders `k`, mics `m`:

```
f0_r(t)      = raw_r(t - delay_r) + b_{c,r}                    [Hz]   (raw telemetry + per-clip bias)
dnu_r        = -lam * nu_r dt + sqrt(2 lam sigma^2) dW_r        [nu in rad/s]
dtheta_r     = nu_r dt                                          [theta in rad, theta_r(0) = 0]
deps_rk      = sqrt(2 D) dW_rk                                  [independent per (r,k), source-side]
Phi_r(t)     = 2 pi Int_0^t f0_r + theta_r(t)
x_m(t)       = sum_{r,k} A_{mrk}(t) cos(k Phi_r(t) + eps_rk(t) + alpha_mrk) + u_m(t)
```

- `lam`, `sigma` are **rig-shared** and **frozen** for candidate 1 (moment-estimated, §5).
- `D` is **one scalar per rig**, initialized from residual moments and then fitted in the spectral MAP.
- `theta_r` is shared across **all orders and all mics**; `eps_rk` is shared across mics
  (source-side) and independent across `(r,k)`.
- Initial residual phase and initial source phase are **independent uniform per harmonic**, shared
  across mics. `alpha_mrk` is the fixed mic response phase; it never enters the expected
  periodogram (see §2, the cross term vanishes).
- `A_{mrk}(t)`, `u_m(t)`: the **existing** harmonic power profile, speed law, mic gains and floor
  (§4). One recording gain across regimes. No tone/noise split, no per-rotor masking.
- `eps` **never** enters the physical shaft RPS.

Degrees of freedom, to be reported in the export's `complexity` block: 3 rig dynamic parameters
(`lam`, `sigma` frozen; `D` fitted), one shared carrier state path per (clip, rotor), one bias per
(clip, rotor) plus one population mean per rotor, and the existing power/floor/speed-law vector.

## 2. `phase_kernel.py` — the shared finite-window kernel (API IS FROZEN)

This module is **agreed and frozen with the evaluator worker (`BaselineLauncher`)**, who will
import it for the legacy descriptive-model adapter so that both adapters predict the *same*
observation through the *same* code. Do not change the signature or the conventions. Do not add a
second entry point. Do not add project imports — this module imports **only** `numpy` and `torch`
(torch lazily inside the dispatch, if you prefer), nothing from `experiments.*`.

```python
def expected_periodogram_from_atoms(atoms, r_tau, *, n_fft, window_sumsq):
    """Expected periodogram of a windowed harmonic atom with a stationary residual phase."""
```

- `atoms`: complex `(..., T)`, `T == n_fft` (raise `ValueError` otherwise). Already windowed:
  `a_t = w_t * A_t * exp(i * phi_t)`, where `A_t` is the **real cosine peak amplitude** of the
  contribution `x_t = A_t cos(phi_t + uniform initial phase)`.
- `r_tau`: real `(..., T)` or `(T,)`, `R(tau)` for `tau = 0..T-1`, broadcast against the leading
  dims of `atoms`. **Used verbatim**: no parametric assumption, no renormalization to `R(0)=1`.
- `n_fft`: int. `window_sumsq`: float, `sum(w**2)`.
- Returns real `(..., n_fft//2+1)`, **directly comparable to
  `experiments.stochastic_fit.data.periodogram(...).power`**.

Exact algorithm — write this in the docstring, it is where silent factor-of-2 and off-by-one bugs
live:

```
L        = 2 * n_fft                       (NOT next_fast_len: L must be an exact multiple of n_fft)
g(tau)   = sum_t a_t conj(a_{t-tau})  =  ifft(|fft(a, L)|^2)   in the natural wrapped layout
R_wrap   = R(tau) at index tau and at index L-tau for tau = 0..T-1, zero in the middle
P_Z[mu]  = Re fft(g * R_wrap)[mu]          (real by Hermitian symmetry; assert in a test)
grid     : f_j = j / n_fft = 2j / L, so n_fft-grid bin j is exactly L-bin 2j — exact subsample,
           never interpolation
M[j]     = 0.25 * (P_Z[2j] + P_Z[(L - 2j) mod L]) / window_sumsq
```

The `0.25` and the negative-frequency fold are the real-signal factors: `x = Re{analytic atom}`
and `E[Z(f) Z(-f)]` vanishes **exactly** under the model's independent uniform initial phases.
`j = 0` and `j = n_fft//2` map to themselves, so DC and Nyquist emerge as `0.5 * P_Z / window_sumsq`
with no special case. `data.periodogram` does **not** double interior bins (it is
`|rfft|^2 / sum(w^2)`), so this must not either.

`P_Z` is real and non-negative by construction (Schur product of two positive-definite kernels);
tiny negatives are roundoff only — **do not clip inside the kernel**.

Backend contract, documented in the module docstring: **both**. If any of `atoms`/`r_tau` is a
`torch.Tensor`, use `torch.fft` and return a `torch.Tensor` (autograd-safe, device-preserving,
usable under CUDA); otherwise use `numpy.fft` and return `float64` numpy. Single dispatch at the
top; one code path afterwards.

Batching: leading dims broadcast. **Never** materialize a `(T, T)` outer product or an
`(M, N, T, T)` intermediate — the FFT autocorrelation is the whole point. Chunking over the batch
is the caller's responsibility (§6).

Also put in this module, as documented module constants, the **frozen front-end convention** so
both adapters read it from one place:
`N_FFT = 16384`, `HOP = 1024`, `SR = 16000`, `BAND_HZ = (30.0, 7900.0)`, and a
`hann_window(n_fft)` returning the **periodic** Hann `np.hanning(n_fft + 1)[:n_fft]` — identical to
`data.periodogram`'s window. Do not re-derive the window anywhere else.

## 3. Residual autocorrelations (in `revised_phase.py`, not in the kernel)

Two, and only two, kernels. `tau` in **seconds**, `k` the order:

- **Conditional / training** (the atom already carries `k * theta_MAP(t)`, so the shaft term is
  already spent): `R_k(tau) = exp(-D |tau|)`. **Only this.** Using the prior OU term here as well
  is the double-counting error the contract forbids.
- **Prior / held-out predictive** (the atom carries only raw telemetry + learned bias, `m = 0`):

```
R_k(tau) = exp( -D|tau|  -  k^2 sigma^2 * [ |tau|/lam - (1 - exp(-lam|tau|)) / lam^2 ] )
```

which is `exp(-0.5 * Var[k dtheta + k... ])` for a **stationarily initialized** integrated OU, plus
the Wiener term `Var[deps] = 2 D |tau|`. Use `expm1`/stable small-argument series:
for `lam*|tau| << 1` the bracket is `|tau|^3 * lam / 3 * (1 + O(lam |tau|))` — expand rather than
cancelling two nearly equal large numbers. Write it once, use it in both `predict_spectrum` and
the renderer's consistency diagnostics.

Exact discrete integrated-OU transition on the state grid with step `dt` (needed by §6):

```
e   = exp(-lam*dt)
F   = [[1, (1 - e)/lam], [0, e]]
Var[nu]        = sigma^2 * (1 - e^2)
Cov[theta, nu] = (sigma^2 / lam) * (1 - e)^2
Var[theta]     = (2 sigma^2 / lam) * [ dt - 2(1 - e)/lam + (1 - e^2)/(2 lam) ]
```

All three must be evaluated with `expm1`-based stable forms and must degrade gracefully as
`lam*dt -> 0` (limits: `Var[nu] -> 2 sigma^2 lam dt`, `Cov -> sigma^2 lam dt^2`,
`Var[theta] -> (2/3) sigma^2 lam dt^3`). A test checks this against Monte-Carlo simulation of the
SDE **and** against the small-`lam*dt` limits.

## 5. Stage 1 — moment initialization (`lam`, `sigma` frozen; `D` initialized)

`estimate_shaft_dynamics(rows, *, gate, config) -> ShaftDynamics`

- **Preregister the gate as module constants with a comment saying they are preregistered and were
  fixed before any estimate was computed**: minimum line SNR in dB over the local floor, minimum
  isolation (nearest competing line from any rotor/order at least X Hz away, X stated in bins of the
  moment front-end), the order range considered, and the minimum number of usable frames. Orders
  failing the gate are excluded — in particular **unresolved overlaps are excluded from the moment
  stage**. Record which orders passed in the diagnostics.
- Extract complex line observations with the **existing** tool `phase_stats.stft_at` (frame-start
  phase reference at the line's own centre frequency — read its docstring, it explains why the
  nearest bin is wrong). The moment stage may use its own shorter window/hop than the frozen
  spectral front end; that is deliberate and must be stated in the diagnostics.
- Form phase increments `dpsi_k(n, L) = arg( z_k(n+L) conj(z_k(n)) ) - k * 2 pi Int raw` over lags
  `L`, unwrap defensively, and use the increment **variance as a function of lag and order**:

```
Var[dpsi_k(tau)] = k^2 * 2 sigma^2 [ tau/lam - (1 - exp(-lam tau))/lam^2 ]  +  2 D tau
```

  The `k^2` scaling is what separates the shared shaft term from the independent term; the lag
  shape is what separates `lam` from `sigma`. Fit `(lam, sigma, D)` numerically by least squares on
  this curve (`scipy.optimize.least_squares`, ordinary, no custom optimizer).
- **Diagnostics, not exactness.** The covariance of the moment estimates is reported as a
  *diagnostic* covariance plus an empirical block-to-block variation across clips. Do **not** call a
  GLS diagonal approximation exact anywhere in code, docstring or export.
- **These moment data must not re-enter the MAP objective as another likelihood factor.** There is
  no separate phase loss stacked on the spectral loss. `lam`, `sigma` are frozen constants in stage
  2; `D` is only *initialized* here.
- **Identifiability honesty.** If the fitted curve does not separate `lam` from `sigma` (flag on the
  Jacobian condition number and on the lag-range coverage relative to `1/lam`), set
  `ShaftDynamics.identified = False`, populate `diagnostics['unidentifiable_reason']`, and
  **propagate the flag into the export**. Never substitute an invented "measured" value. A caller
  that receives `identified=False` must be able to see it.

```python
@dataclass(frozen=True)
class ShaftDynamics:
    lam: float          # 1/s
    sigma: float        # rad/s, stationary std of nu
    d_init: float       # rad^2/s

    diagnostics: dict[str, Any]
```

## 6. Stage 2 — the plug-in composite MAP fit

`fit_revised(rows, *, rig_id, dynamics, config, device="cpu", progress=None) -> dict`

`rows`: `Sequence[tuple[str, Clip]]` — clip id and a 16 kHz `Clip` whose `rps` track is the **raw**
telemetry (the manifest names the `rps_key`; refined labels are not used to fit).

**Latent state.** Per (clip, rotor), a dense grid at `config.state_rate_hz` (manifest; default
proposal 200 Hz), **independent of `n_fft`/`hop`**. State `z_j = (theta_j, nu_j)`.
Parameterize **non-centred/whitened**: `z_{j+1} = F(dt) z_j + L(dt) e_j` with `L L^T = Q(dt)` (2x2
Cholesky of the exact covariance in §3) and free parameters `e_j ~ N(0, I)`; `theta_0 = 0` (gauge)
and `nu_0 = sigma * e_0` (stationary initial law). The state log-prior is then exactly
`0.5 * sum e^2` — one exact Gaussian integrated-OU prior, isotropic and well conditioned, and the
MAP is identical to the MAP in `z` coordinates because the map is linear with constant Jacobian.
State it in the docstring in exactly those terms.

**Dense interpolation to audio rate.** `theta` at 16 kHz from the state grid by **cubic Hermite**
interpolation using `(theta_j, nu_j, theta_{j+1}, nu_{j+1})` — consistent by construction, since
`nu = dtheta/dt`. This **omits the OU bridge variance inside a grid interval**. Label it exactly
that way in the docstring and in the export diagnostics: *grid approximation; the fit must be
checked for convergence as the state grid refines*. Do **not** add a bridge kernel. Expose
`state_rate_hz` so a refinement sweep is a configuration change, and emit the grid rate into the
export so a convergence sweep is auditable.

**Atoms.** For clip `c`, rotor `r`, frame `n` starting at sample `t0`:

```
Phi_r[t]   = 2 pi cumsum( (raw_r[t - delay_r] + b_{c,r}) / SR )  +  theta_r[t]      (audio rate)
a_{k,n}[i] = w[i] * A_rk(t0+i) * exp(i * k * Phi_r[t0+i]),   i = 0..n_fft-1
```

This is the **actual within-window integrated carrier** — never a frame-mean speed, never a
chirp-width heuristic, never `exp(i*theta_at_frame_centre)` factored out of the window.

**Expected spectrum.** `M[m, n, f] = floor[m, n, f] + sum_{r,k} gain[m, r] * S_{r,k,n}[f]` where
`S = expected_periodogram_from_atoms(atoms, r_tau=exp(-D|tau|), n_fft, window_sumsq)`. The mic gain
is a time-invariant scalar multiplying the per-(r,k,frame) shape, so the kernel is called **once per
(rotor, order, frame)**, not once per mic — this is the difference between a feasible fit and a
20x blowup. All components are summed **in power**: the cross terms vanish exactly under
independent uniform initial phases, so crossing orders stay shared continuous states and are never
assigned to bins.

**Objective** (one objective, one prior; state it as such):

```
L = temperature * sum_i a_i * sum_{m, f in band} ( I_i / M_i + log M_i )
    + 0.5 * sum e^2                                    (state prior)
    + bias prior + parameter priors
```

- Band fixed `30..7900 Hz`, fixed mics. Never narrow the band.
- `a_i`: positive weights **normalized per unique audio duration** — `a_i = hop / n_fft` for a
  frame, and **identical duplicated windows split their exposure** (if the same `(clip_id,
  start_sample)` appears `d` times, each copy gets `a_i / d`). Implement this as a small explicit
  `composite_weights(frame_keys)` helper and regression-test it.
- Call it, in code and docstring, a **marginal composite risk / plug-in composite MAP**. It is
  **not** an exact joint NLL, not evidence, not a posterior, and frame counts are **not** evidence
  counts. Never derive uncertainty from cellwise Hessians or the nominal frame count.
- `temperature` comes from the manifest (`composite.temperature`), default `1.0`, and is described
  as *calibrated on planted/baseline data and then frozen* — the code reads it, it does not tune it.
- Bias prior: `b_{c,r} ~ N(mu_r, s_b^2)` with `s_b` a proper, manifest-supplied Hz scale and `mu_r`
  a free per-rotor population mean under a broad proper prior. Report, in diagnostics, the
  confounding between `b_{c,r}` and the clip-mean of `nu_r/(2 pi)` (finite-record bias vs. slow OU).
  Do **not** "fix" it with a second free path.
- `log D` gets a broad Gaussian prior. Document that this prior is **not** conjugate to the noisy
  moment-derived `D` — it is simply a prior on a fitted parameter.
- Optimizer: **ordinary `torch.optim.Adam`**. Nothing else. Iterations/lr/seed from the manifest.

**Compute discipline.** Chunk over frames (`config.frame_chunk`), compute the chunk's composite
term, call `backward()` per chunk and accumulate gradients, free the chunk. Peak memory is bounded
by `frame_chunk * K * 2 * n_fft` complex entries — size the default so that is a few hundred MB.
Optionally minibatch frames per step (`config.frames_per_step`, `None` = all). No `(M, N, T, T)`
anything. Put the arithmetic of the cost estimate in the module docstring so the next reader can
check feasibility without rerunning it.

## 7. The other three public APIs

`predict_spectrum(export, clip, *, n_fft=N_FFT, hop=HOP, mode="prior") -> np.ndarray  # (M, N, F)`

- `mode="prior"` (**default, the held-out path**): atoms carry raw telemetry + the *learned bias
  law* (the population mean `mu_r`, since a new clip's `b` is unknown), `m = 0`, and `R_k` is the
  **full prior** kernel (OU + `D`) of §3. It **never** touches the clip's audio, never runs an
  optimization, never reads a refined label, and never uses a stored training MAP path.
- `mode="training_replay"`: diagnostic only; requires `clip.clip_id` to be present in the export's
  training diagnostics and **raises** otherwise. Uses the stored MAP path in the atom and the
  conditional `exp(-D|tau|)` kernel. Stored MAP paths are diagnostics and are never a default
  predictive input for a new clip.
- Shape and units match `data.periodogram(clip, n_fft, hop).power` exactly.

`render_revised(export, rps, *, sample_rate=16000, sample_rate_native=44100, n_mics=8, seed=0)`

- Primary renderer: **one fresh OU draw** of `(theta, nu)` and fresh `eps`, at the native rate,
  driven by `rps` (raw telemetry) + the learned bias law. No refined labels, no inferred
  corrections, no posterior path.
- Synthesize `sum_{r,k} A_{mrk}(t) cos(k Phi_r(t) + eps_rk(t) + alpha_mrk) + u_m(t)` at
  `sample_rate_native`, then `stage2.antialias(...)` (import it, do not reimplement, do not change
  it) and then `clips.decimate(...)` unchanged. No per-rotor masking.
- Returns a frozen dataclass:

```python
@dataclass(frozen=True)
class RevisedRender:
    audio: np.ndarray          # (M, T) float32 at sample_rate
    physical_rps: np.ndarray   # (R, T) realized interval-average shaft rev/s
    reference_rps: np.ndarray  # (R, T) the raw telemetry reference the arms share
    sample_rate: int
    diagnostics: dict[str, Any]
```

- `physical_rps[r, i] = (Phi_r(t_{i+1}) - Phi_r(t_i)) / (2 pi * dt_out)` — the **interval average**
  from the exact phase, **excluding `eps`**, on the output grid, with **exactly the same length and
  timeline as `audio` after decimation**. Read `clips.decimate` to match the resampled length
  exactly; do not modify it.
- `reference_rps` is the shared raw telemetry reference all arms are scored against. Both are
  emitted; the export/consumer decides which is primary (MAE against `reference_rps` is primary,
  `physical_rps` is the diagnostic).

`infer_carrier(export, clip, *, config=None) -> CarrierTrack`

- The **diagnostic** telemetry-conditioned MAP track — never called implicitly inside
  `predict_spectrum` or `render_revised`.
- Returns `time_s (S,)`, `nu_hz (R, S)` (`= nu / 2 pi`), `theta_rad (R, S)`, `bias_hz (R,)`,
  `total_hz (R, S) = raw(t - delay) + b + nu/2pi`, plus diagnostics.
- Docstring must say it is a **MAP** track (plug-in), not a posterior mean, and that comparison
  against the existing refined tracks is **diagnostic only** — disagreement is not a failure and
  refined tracks are not ground truth.

## 12. AMENDMENTS — these override §§6, 7, 9 wherever they conflict

### 12.1 State-grid resolution and how to generate the state (Main, quantitative)

Bridge error scales with **k squared**. The integrated-OU bridge phase variance inside one grid
interval is `O(lam * sigma^2 * dt^3)`, and the atom carries `k * theta`, so order `k = 100`
multiplies that omitted variance by `10^4`. **A 16 ms state grid may be far too coarse even for a
slow OU.** Therefore:

- **Do not choose `state_rate_hz` from `lam` or from the hop.** Choose it from a planted
  convergence check: plant a high order `k = 100` with `sigma ~ 6 rad/s` and `lam ~ 6 /s`, and
  verify that the fitted/predicted spectrum converges as the state grid refines. A **1-2 ms grid
  (500-1000 Hz) may be required**; the default in `FitConfig` must be justified by that check, not
  asserted. Emit the grid rate and the convergence evidence into the export diagnostics.
- **Generate the state with a vectorized causal filter, not a Python per-state loop.** `lam` is
  frozen and `dt` is uniform, so the whitened recursion is linear time-invariant and closed form.
  With the exact 2x2 `Q(dt)` and its lower Cholesky `L = [[a, 0], [b, c]]`:

```
nu_j    = e * nu_{j-1} + (b * e1_{j-1} + c * e2_{j-1})          e = exp(-lam*dt)
theta_j = theta_{j-1} + ((1 - e)/lam) * nu_{j-1} + a * e1_{j-1}
```

  `nu` is an AR(1) driven by `b*e1 + c*e2`: evaluate it as a **causal convolution with the kernel
  `e^{-lam*dt*n}`** (FFT convolution, or an existing project/`torch`/`scipy` primitive — do not
  write new machinery), and `theta` is then a **cumulative sum** of
  `((1-e)/lam) * nu_{j-1} + a * e1_{j-1}`. Both are differentiable, `O(S log S)`, and run batched
  over (clip, rotor) on GPU. A 16 s clip at 1 ms is 16000 states per rotor — a per-state autograd
  loop is not acceptable; this closed form is.
  Guard the exponential-kernel convolution against underflow/overflow for large `lam*dt*S` (the
  kernel decays; truncate it where it underflows float32 and say so in a comment).
- This stays an **ordinary dense-grid MAP with one exact prior**. It is still simpler than a
  bridge-likelihood framework, which you must **not** add. This amendment is accuracy guidance, not
  a licence for extra abstractions.
- The Hermite-interpolation caveat in §6 stands and must still be labelled as a grid approximation
  that omits the intra-interval bridge variance; at a 1-2 ms grid it is small, which is exactly
  what the convergence check has to demonstrate rather than assume.
